### `_merge_Module2.py` (new)
Pure zip + ElementTree surgery, the same discipline as `_splice_media.py`
(a python-pptx round-trip would strip the PollEverywhere `tags` rels).
Everything comes across verbatim — slide XML, `<p:timing>` builds,
groups, media, notes and the poll payload.

    python _merge_Module2.py               # full run
    python _merge_Module2.py --no-rebuild  # merge the video deck as-is

- The two decks share one theme, one master and one layout
  (`slideLayout7`) BYTE FOR BYTE — both are generated by the same helper
  layer. Checked before writing the script; the copied video slides are
  therefore pointed at the base deck's layout and no master/theme parts
  are duplicated. **If that ever stops being true the merge has to copy
  the master too.**
- Copied parts get a `vd_` prefix (`ppt/slides/vidNN.xml`,
  `ppt/notesSlides/vidNN_notes.xml`, `ppt/media/vd_imageN.png`,
  `ppt/tags/vd_pe19_tag1.xml`), each part's own `.rels` copied
  recursively, and rIds remapped in a SINGLE pass (a sequential replace
  clobbers itself when the id spaces overlap — the bug `_splice_media`
  hit on slide 13).
- The cached digit inside each `<a:fld type="slidenum">` is rewritten to
  the new display number, so the deck reads right before PowerPoint
  recomputes the field.

### Gotchas learned this session
- **`<a:xfrm>` child order in a grpSp is off, ext, chOff, chExt.** Any
  other order is silently misparsed: group children collapse (text goes
  vertical one-letter-per-line, pictures/charts vanish). No error is
  raised — caught only by render comparison.
- CT's poll slides are static images and her deck has no animations —
  content reference only.
- OMML equation shapes DO expose their m:t text to the animation engine's
  shape collector — select them with `t:` prefixes ("t:E D"), not `osp:`.
- `t:` selectors containing `#` (e.g. "#Note") collide with the `#n`
  suffix syntax — write "t:#Note#1".
- `_add_convention_box` emits TWO shapes (rounded rect + text box) — put
  both in the same animation beat (and group them in the grouping pass).
- PowerShell COM: `$pp.Visible = -1` (MsoTriState), not `$true`; the
  slideshow window is found reliably via EnumWindows on the POWERPNT pid
  + class `screenClass` (FindWindow raced/failed; `SlideShowWindow.HWND`
  returns null through PS interop).
